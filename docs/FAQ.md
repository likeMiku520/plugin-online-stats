# 常见问题

## 总浏览量为什么和 Halo 后台、主题显示的不一样

1.3.3 起两者口径已经一致：插件和 Halo 一样**累加全部 Counter 资源**（文章、独立页面等都算）。

如果你看到的数字仍然偏小：

- 升级后需要等 5 分钟左右，插件才会同步一次官方计数器（也可以在插件设置里随便保存一次，或重启插件加快）
- 修正值现在是**直接写进 Halo 计数数据**的，所以后台和主题都会一起变化，见下一节

## 官方总浏览量修正值怎么用

填一个整数，插件会把这个数字**写进 Halo 自己的计数数据**（一个专用的 Counter，不对应任何真实文章）。因为 Halo 的站点统计是累加全部 Counter，所以：

- 插件后台的「总浏览量」会增加
- **Halo 后台仪表盘的总浏览量也会增加**
- **主题前台显示的总浏览量同样会增加**

典型场景：换过博客或迁移过数据，Halo 计数器从 0 重新开始，但旧站历史浏览量有几千，把那个数字填进来就能对上总数。

填 0 或留空会把之前写入的修正清除，总数回到 Halo 的原始值。这个修正只影响站点总数，不会改动任何一篇文章自己的浏览量。

保存后几秒内生效；如果页面提示写入失败，说明当前 Halo 版本不接受这种计数器名称，把提示内容发出来即可。

## 在线人数正常，但历史记录一直是空的

先看后台「在线访客统计」页顶部有没有红色提示条，再对照「记录状态」卡片里的 `落库 / 失败` 计数。

- `失败 > 0`：把红色提示条里的异常内容发出来，通常是数据库写入被拒绝或自定义模型注册失败
- `落库 = 0 且 失败 = 0`：持久化任务还没跑过，等 20 秒再看（落库是每 20 秒一个周期，不是实时）
- 页面提示「暂无访客记录」但访问量正常：确认插件是启用状态，且日志里没有 `online-stats` 相关报错

历史记录从插件启用后才开始积累，升级前没有历史数据可以补。

## 查询属地一直提示「接口没有返回有效属地」

1.2.1 起，详情里会显示具体原因和本次使用的接口地址，先看那两行：

- `接口返回 HTTP xxx`：接口不可达或被限流
- `响应不是合法 JSON`：多半是接口地址配错了，或者接口返回了 HTML 错误页
- `接口返回了无法识别的数据：xxx`：接口能通，但返回结构不是插件认识的那两种

常见原因和解决：

1. **设置里还存着旧版地址**。1.1.x 的默认接口是 `ip-api.com`，1.2.0 换成 `api.mir6.com`。插件会自动忽略旧的 `ip-api.com` 地址，但如果你的设置里手写过别的地址，去「插件设置 → IP 属地查询接口」确认它是：

   ```
   https://api.mir6.com/api/ip?ip=%s&type=json
   ```

   `%s` 是 IP 占位符，不能丢。

2. **接口限流**。免费接口通常有频率限制，隔几秒再点一次。

3. **服务器出网被限制**。Halo 所在服务器如果不能访问外网 HTTPS，任何接口都会失败；可以先用 `curl` 在服务器上测一下。

查询失败不会写入记录，也不会缓存，可以直接重试。

## 怎么区分真人和机器人

插件会在落库时给每条记录打上 `bot` 标记，判定规则（满足任意一条即视为机器人）：

- User-Agent 命中爬虫特征：`bot`、`crawler`、`spider`、`python-requests`、`curl/`、`wget`、`go-http-client`、`okhttp`、`headlesschrome`、`bytespider`、`petalbot` 等
- 没有上报浏览器指纹：正常浏览器会带屏幕分辨率、窗口尺寸、时区、语言，四条全空的基本不是真实浏览器

列表用「真人 / 机器人 / 全部」三个标签页分开，默认只显示真人；机器人记录仍然保留，方便你确认是不是被刷了。

被误判的真人（例如禁用 JS 的浏览器、某些极简客户端）不会有指纹，也会进机器人分组，这是有意的取舍。

## 数据存在哪里，重启会丢吗

- 在线状态：进程内存，重启清空，这是正常的
- 历史记录：Halo 数据库里的 `VisitorRecord` 资源，重启不丢
- IP 属地缓存：进程内存，重启后需要重新点一次「查询属地」

过期记录每 30 分钟清理一次，规则来自设置里的「保留天数」和「最大条数」。

## 升级后需要注意什么

- 插件名没变，直接上传新 jar 覆盖即可，历史数据保留
- 新增/修改的设置项会出现在插件设置里，旧值不会丢
- 后台是单页应用，升级后建议刷新一次后台页面，避免看到旧的前端代码

## 为什么同一个人开了两个标签页只算一个访客

访客按 `IP + User-Agent` 聚合，同一设备同一浏览器算同一个人；换网络或换浏览器会被算成新访客。
