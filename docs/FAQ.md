# 常见问题

## 总浏览量为什么和 Halo 后台、主题显示的不一样

1.3.3 起口径已经对齐：插件和 Halo 一样累加全部 Counter 资源，文章、独立页面都算在内。

如果数字仍然偏小，通常是还没同步——插件每 5 分钟读一次官方计数器，重启插件或在设置里随便保存一次会立刻触发。

## 官方总浏览量修正值怎么用

填一个整数，插件把它写进 Halo 自己的计数数据（一个专用的 Counter，不对应任何真实文章）。Halo 的站点统计是累加全部 Counter，所以插件后台、Halo 仪表盘、主题前台的总浏览量会一起增加。

换过域名或者迁移过数据时有用：Halo 计数器从 0 重新开始，旧站的历史浏览量填进来就能对上总数。填 0 或留空会清除之前的修正，总数回到原始值。这个修正只影响站点总数，不改动任何一篇文章自己的浏览量。

## 在线人数正常，但历史记录一直是空的

先看「在线访客统计」页顶部有没有红色提示条。

- 有红色提示条：里面是具体的写入异常，贴到 [issues](https://github.com/likeMiku520/plugin-online-stats/issues) 就能定位
- 没有任何提示、列表空：落库是每 20 秒一个周期，等一会儿再看
- 有访问量但一直没记录：确认插件是启用状态，并检查 Halo 日志里有没有 `online-stats` 的报错

历史记录从插件启用之后才开始积累，之前的访问补不回来。

## 查询属地提示「接口没有返回有效属地」

详情里会写出具体原因和这次用的接口地址：

- `接口返回 HTTP xxx`：接口不可达或被限流
- `响应不是合法 JSON`：地址多半配错了，或者接口返回了 HTML 错误页
- `接口返回了无法识别的数据`：接口能通，但返回结构不是插件认识的格式

常见的报错和原因：

- `接口返回了网页而不是数据`：接口地址指向的服务已经不再返回数据，换一个地址即可
- `响应不是合法 JSON`：地址多半配错了
- `接口没有查到该地址的属地`：接口能通，但那个 IP 查不到结果

插件会忽略几个已经失效的默认地址（`ip-api.com`、`api.mir6.com`），遇到它们会自动换成当前默认接口，所以从旧版本升级不用手工改设置。手写过的其它地址不会被改动，可以去「插件设置 → IP 属地查询接口」确认，格式是：

```
https://whois.pconline.com.cn/ipJson.jsp?ip=%s&json=true
```

`%s` 是 IP 占位符，不能丢。免费接口一般有频率限制，隔几秒再点；服务器完全不能出网的话任何接口都会失败，可以先在服务器上 curl 一下确认。查询失败不写入记录也不缓存，可以直接重试。

## 怎么区分真人和机器人

记录落库时会打上 `bot` 标记，命中任意一条就算机器人：

- User-Agent 命中爬虫特征：`bot`、`crawler`、`spider`、`python-requests`、`curl/`、`wget`、`go-http-client`、`okhttp`、`headlesschrome`、`bytespider`、`petalbot` 等
- 完全没有浏览器指纹：正常浏览器会带屏幕分辨率、窗口尺寸、时区、语言，四条全空的基本不是真实浏览器

列表默认只显示真人，可以用「真人 / 机器人 / 全部」切换，机器人记录仍然保留，方便确认是不是被刷了。禁用 JS 的浏览器和极简客户端也会被判成机器人，这是有意的取舍。

## 数据存在哪里，重启会丢吗

在线状态只在进程内存里，重启清空，这是正常的。历史记录是 Halo 数据库里的 `VisitorRecord` 资源，重启不丢。IP 属地缓存也在内存里，重启后重新点一次「查询属地」即可。

过期数据每 5 分钟清理一次，规则来自设置里的保留天数和最大条数。

## 升级后需要注意什么

直接传新 jar 覆盖安装，历史数据保留；新增的设置项会出现在插件设置里，旧值不会丢。后台是单页应用，升级后刷新一次页面，免得看到旧的界面代码。

2.0.0 起对话按设备归属，1.x 时代按 IP 存的旧对话不会再显示（记录本身会随保留天数清掉）。访客端脚本也变了，如果访客刷新后行为不对，让浏览器强刷一次。

## 为什么同一个人开了两个标签页只算一个访客

访客按 `IP + User-Agent` 聚合，同设备同浏览器算一个人，换网络或换浏览器就是新访客。给访客发消息用的是同一套标识，所以对话也只属于那一台设备。

## 访客端的对话卡片，刷新之后去哪了

访客端不往浏览器里存任何东西。刷新页面后卡片和右下角的按钮都会消失，直到后台再发一条新消息才重新出现。如果刷新后窗口和按钮还在，说明浏览器跑的仍是旧脚本，强刷一次就好。

## 开了「仅允许 HTTPS」之后对话整个不工作了

这一项默认关闭，因为它要求服务端能确认请求是 HTTPS。站点走 CDN 或反向代理时，服务端往往只看得到回源那一跳（例如 CDN 用 HTTPS 对外、回源走 HTTP），确认不了就会拒绝对话接口——前台表现为对方永远收不到消息。

保持关闭即可，或者把这一项关掉再试；确认代理会把 `X-Forwarded-Proto: https`、`Forwarded`、`CF-Visitor` 之一传给 Halo，再考虑打开。
