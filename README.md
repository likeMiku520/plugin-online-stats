# 在线访客统计

给 Halo 2.x 用的访客统计插件：看看此刻有几个人在站上、他们从哪来、看了什么，历史访客也会存下来。

- 作者：fufu大王
- 网站：https://blog.fufu520.cn
- 仓库：https://github.com/likeMiku520/plugin-online-stats
- 需要 Halo 2.25 及以上

安装：后台 → 插件 → 安装 → 上传 `plugin-online-stats-<版本>.jar`，启用。装好后左侧菜单的「仪表盘」分组下会多出「访客统计」和「访客明细」两项。

## 两个页面

### 访问统计

顶部四张卡片：当前在线、历史访客、今日新增、会话数，前三个各自标出真人和机器人各多少。右上角可以在「全部 / 真人 / 机器人」之间切换，整页数据跟着变——包括曲线、分布和文章排行。

三张卡片下面是最近 7 天的访问曲线，可以切到 30 天或 90 天。

再往下是四张排行：浏览器来源、操作系统来源、来源站点、页面地址。每张只列前十五名，每一行都能点开，看到具体是哪些访客贡献的。页面地址那一行同时显示页面标题和它所在的路由，标题相同的两个页面不会混成一条。

前两张和来源站点按**访客**计：一台设备读十个页面，在 Edge 那一行仍然只算一次。页面地址按**浏览量**计，因为它回答的是这个页面被看了多少次。两种口径在图标题旁边分别标注。

整个页面每 5 秒自动刷新一次，新的访问不用手动重新加载。

最后是文章排行，可以按总浏览量、访客数、今日浏览、平均停留排序。

三个筛选口径是一致的：「全部」的数字永远等于「真人」加「机器人」。判定机器人用的是启发式规则——User-Agent 命中常见爬虫，或者完全没上报屏幕、时区这些浏览器信息。

站上的每个页面都会计数：首页、归档、标签、独立页面和文章页一样进访客数、浏览量和页面排行。文章排行是唯一的例外，它只列文章页，所以那一栏的合计小于上面的总量。

页面排行按真实浏览量排：一台设备读了几篇文章就算几次，不是只算最后停留的那一页。同一个路由带不同的查询参数算作同一页。

### 访客明细

在线访客和历史记录在同一张表里，可以按真人 / 机器人分组、按在线状态筛、搜索、排序、翻页（右下角能直接填页码跳过去，也能一键回首页或末页）。搜索会同时匹配 IP、属地、页面标题，以及**访客说过的聊天内容**。

列表左侧的勾选框一直开着，随时可以多选。表头那个是全选本页的行。

每行右侧的「更多」会打开详情抽屉：UA 解析、屏幕尺寸、语言、时区、来源页面、首次来源、访问经过的每个页面和停留时长，以及和这位访客的对话。来源页面和首次来源后面有「打开」按钮，点一下在新标签页访问那个地址。没有属地记录时，列表里会出现「查询属地」，点了就地查询。

表格上方的操作栏分两个页签：

| 页签 | 能做的事 |
| --- | --- |
| 访客数据 | 导出选中数据 / 导出全部数据 / 清除选中数据 / 清除全部数据 |
| 聊天记录 | 导出选中聊天 / 导出全部聊天 / 清除选中聊天 / 清除全部聊天 |

访客数据和聊天记录都导出成带缩进的 JSON：访客按地理位置、最后页面、来源、设备、对话分组，聊天按会话列出每条消息的时间、发送方和正文。导出范围跟当前筛选一致。清除前会二次确认；**清除一位访客会连他的聊天记录一起删掉，同时把这些访问从统计数据里扣掉**，所以明细里少一条，统计页的数字也会同步减少。

「清除全部数据」是从头开始：访客记录、聊天记录、按天和按文章的历史统计全部删除，官方浏览量的修正值归零。

### 会话窗口

会话数卡片右下角的按钮会打开一个悬浮窗，列出所有有过对话的访客：属地、最后一条消息、最后对话时间、聊了多少条。窗口顶部是会话数和总消息数，还有独立的搜索框。没查过属地的访客旁边有「查询属地」，点开某一位会打开和「更多」相同的详情抽屉。

手机上这个窗口默认占屏幕高度的 40%，按住底部的横条往下拖，窗口随手指长高，松手过了一小段就全屏、没到就回弹。全屏后往上拖先回到默认高度，再往上拖一次才收起、变回悬浮按钮；默认高度下也可以直接往上拖收起。两个方向都跟手，都有过渡动画。

## 即时通讯

访客明细里可以给某位访客发消息，对方页面上会弹出对话框，他可以直接回复，在同一个抽屉里能看到。默认关闭，在插件设置里打开「即时通讯」才可用。

几个需要知道的行为：

- 对话属于**具体那台设备**（IP + User-Agent），不是 IP。同一网络下的另一台电脑、同一个人的另一个浏览器，都是各自独立的对话。
- 访客关掉对话框后，刷新页面不会再看到它，直到有新的消息发过去。
- 访客当时登录了 Halo 就显示账号名和头像，没登录则显示「访客」。
- 每段对话保留最近 100 条消息，超过的从最早的开始删。消息条数不设上限，对话数量也不设上限。
- 消息随「访客记录保留天数」一起清理。所有页面都支持，访客不需要停在文章页也能收到。

这不是端到端加密：服务端要存着消息才能在没有人在线时投递、并在后台展示，所以能直接读数据库的人仍然看得到内容。插件保证的是传输走 HTTPS、只有对应设备和超级管理员能读到这段对话、以及记录会按期清掉。

## 自动访客消息

第一次来到站点的访客，页面会直接弹出对话框把内容给他看，他也可以像平常一样接着回复。内容、发信人名称、发信人头像都可以在设置里改。

- 同一段内容每台设备只会收到一份；改过内容后，下次访问时收到的是新内容，不会把旧的再发一遍。
- 察觉不到浏览器信息、或者 UA 命中常见爬虫的，不发送。
- 打开这一项会一并启用对话通道，不需要另外打开「即时通讯」。
- 访客自己先开口的对话不会被插入公告。

## 设置项

设置页按功能分成三组。

| 分组 | 设置项 |
| --- | --- |
| 统计设置 | 心跳间隔、在线判定超时、本站域名、官方总浏览量修正值、后台显示访客 IP 地址 |
| 即时通讯 | 开关、仅允许 HTTPS、对话头像、自动访客消息的内容与发信人 |
| 数据与属地 | IP 属地查询接口、附加请求参数、要显示的字段、保留天数、最大条数 |

「官方总浏览量修正值」是给换过域名或迁移过数据的人用的：填一个整数，会直接写进 Halo 的计数数据里，后台仪表盘和主题前台会一起增加；填 0 会把之前的修正清掉。

「本站域名」用来在来源站点里排除站内跳转，填了之后自己站内的链接不会被当成外部来源。

属地相关的三项：

- **IP 属地查询接口**：用 `{ip}` 表示要查询的地址，默认是 `https://api.mir6.com/api/ip_json?ip={ip}`。填别的接口也可以，只要把地址的位置写成 `{ip}`。
- **附加请求参数**：每行一个 `名称=值`，拼在接口地址后面，用来带 token、key 或语言这类参数。
- **要显示的字段**：每行一个 `显示名称=接口返回里的位置`，例如 `城市=data.city`，点号可以进到嵌套对象里。显示什么、叫什么名字都由这里决定。

## 它是怎么跑的

1. 前台加载插件提供的 `online-stats.js`（每页只初始化一次，主题用 swup 之类的无刷新换页也不会重复挂载），按间隔上报心跳，脚本自己不渲染任何界面。
2. 插件按 `IP + User-Agent` 维护在线名单，超过「在线判定超时」没有心跳就算离线。
3. 心跳聚合成两份统计：每篇文章的 `ArticleStat`、每天的 `DailyStat`。两者都留着每台设备的贡献，所以既能按真人 / 机器人拆开，也能在清除访客时精确扣减。
4. 浏览量按「进入一次页面」算一次，停在页面上不动不会重复计数；停留时长按心跳间隔累加。
5. 在线访客每 20 秒落库成 `VisitorRecord`，后台列表会把内存里的在线访客合并进来。
6. 启动后每 5 分钟同步一次 Halo 官方计数器，同时按保留天数清理过期数据。

写入撞车时会取回对方那一份、把内存里的数字合并进去再重试，三次都失败才放弃；「今日浏览」记着它属于哪一天，同一天之内只增不减。这两个处理是为了避免统计数字无故往回掉。

## 数据与隐私

会记录：IP（后台展示可以关掉，但仍然用于区分访客）、User-Agent、正在看的页面 URL 与标题、来源页面，以及浏览器上报的屏幕尺寸、语言、时区。

存在哪：在线状态只放进程内存，重启就没了；历史记录存在 Halo 数据库的 `VisitorRecord` 资源里，按设置的天数（默认 90 天）和条数（默认 5000 条）自动清理。IP 属地不会自动查询，只有点了按钮才把那个 IP 发给设置里的接口（默认 `api.mir6.com`），结果在内存里缓存 7 天。

## 已知限制

- 在线人数是「最近有心跳的设备数」，不是账号数；同一个人换浏览器会算两次。
- 停留时长靠心跳累计，切到后台标签页或断网期间不一定准。
- 归属地依赖第三方接口，查不到时会留空，可以自己换接口地址。
- 机器人识别是启发式的，判断依据见上文。
- 排行只列前十五名，名次之后的数据仍然算在总数里，只是不在榜上显示。
- 统计页的数字来自保留下来的访客记录和汇总；把访客记录清掉之后再来的访问，会从那一刻重新开始累计。
- 全部页面从 3.5.2 开始计数，更早的访问只有文章页被记下来，这部分补不回来。

## 构建

需要 JDK 21、Node 20+、pnpm 9。

```
# macOS / Linux
./gradlew build

# Windows
gradlew.bat build
```

产物在 `build/libs/plugin-online-stats-<version>.jar`。注意先构建前端再打包：`ui/build/dist` 是前端产物的来源，`gradle clean` 会把它删掉，这时打出来的 jar 会缺少后台界面。
