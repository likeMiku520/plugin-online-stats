# 在线访客统计

给 Halo 2.x 用的访客统计插件：看看现在有几个人在站上、他们都从哪来、看了什么，历史访客也会存下来。

- 作者：fufu大王
- 网站：https://blog.fufu520.cn
- 仓库：https://github.com/likeMiku520/plugin-online-stats

安装：Halo 后台 → 插件 → 安装 → 上传 `plugin-online-stats-<版本>.jar`，启用。菜单在后台「系统」分类下。

## 两个页面

**访问统计**是总览：当前在线、总浏览量（直接读 Halo 自己的计数器，跟主题和后台显示的数字一致）、总访客、今日浏览、今日访客、文章数；下面是最近 90 天的曲线（可以切 30 天 / 7 天）、浏览器与系统分布、来源站点、文章排行。分布和排行的每一行都能点开，看到具体是哪些访客贡献的。

**访客明细**是名单：在线访客和历史记录在一起，可以按真人 / 机器人分组、按在线状态筛、搜索、排序、翻页（右下角能直接填页码跳过去）。列表里就能点「查询属地」，也可以点「更多」打开详情抽屉，看 UA 解析、屏幕尺寸、语言、时区、CPU 核心数、设备内存、网络类型、来源页面和停留情况。

统计口径上只有文章页算数：首页、归档、标签页不进访客数，也不计文章浏览量。

## 即时通讯

访客明细里可以对某位访客发消息，对方页面上会弹出一个对话框，他可以直接回复，你在同一个抽屉里看到。默认是关的，在插件设置里打开「即时通讯」才能用。

几个需要知道的行为：

- 对话属于**具体那台设备**（IP + User-Agent），不是 IP。同一网络下的另一台电脑、同一个人的另一个浏览器，都是各自独立的对话。
- 访客关掉对话框后，刷新页面就不会再看到它，直到你再发一条新消息。
- 访客如果当时登录了 Halo，后台会显示他的账号名和头像；没登录就显示「访客」。
- 消息按「访客记录保留天数」一起清理。

这不是端到端加密：服务端要存着消息才能在你不在线时投递、并在后台展示给你，所以能直接读数据库的人仍然看得到内容。插件保证的是传输走 HTTPS、只有对应设备和超级管理员能读到这段对话、以及记录会按期清掉。

## 设置项

心跳间隔、离线判定超时、本站域名（用来在来源里排除站内跳转）、官方总浏览量修正值、后台是否显示访客 IP、即时通讯开关、IP 属地查询接口、访客记录保留天数与最大条数。

「官方总浏览量修正值」是给换过域名或迁移过数据的人用的：填一个整数，会直接写进 Halo 的计数数据里，所以后台仪表盘和主题前台会一起增加；填 0 会把之前的修正清掉。

## 它是怎么跑的

1. 前台加载插件提供的 `online-stats.js`（每页只初始化一次，主题用 swup 之类的无刷新换页也不会重复挂载），每 15 秒上报一次心跳，脚本自己不渲染任何界面。
2. 插件按 `IP + User-Agent` 维护在线名单，默认 60 秒没有心跳就算离线。
3. 心跳聚合成两份统计：每篇文章的 `ArticleStat`、每天的 `DailyStat`。
4. 浏览量按「进入一次页面」算一次，停在页面上不动不会重复计数；停留时长按心跳间隔累加。
5. 在线访客每 20 秒落库成 `VisitorRecord`，后台列表会把内存里的在线访客合并进来。
6. 启动后每 5 分钟同步一次 Halo 官方计数器；每 5 分钟也顺便按保留天数清理过期数据。

## 数据与隐私

会记录：IP（后台展示可以关掉，但仍然用于区分访客）、User-Agent、正在看的页面 URL 与标题、来源页面，以及浏览器上报的屏幕尺寸、语言、时区、CPU 核心数、设备内存、网络类型。

存在哪：在线状态只放进程内存，重启就没了；历史记录存在 Halo 数据库的 `VisitorRecord` 资源里，按设置的天数和条数自动清理。IP 属地不会自动查询，只有点了按钮才把那个 IP 发给设置里的接口（默认 `whois.pconline.com.cn`），结果在内存里缓存 7 天。

## 已知限制

- 在线人数是「最近有心跳的设备数」，不是账号数；同一个人换浏览器会算两次。
- 停留时长靠心跳累计，切到后台标签页或断网期间不一定准。
- 归属地依赖第三方接口，查不到时会留空，可以自己换接口地址。
- 机器人识别是启发式的：UA 命中常见爬虫，或者完全没上报屏幕、时区等浏览器信息。

## 构建

需要 JDK 21、Node 20+、pnpm 9。

```
# macOS / Linux
./gradlew build

# Windows
gradlew.bat build
```

产物在 `build/libs/plugin-online-stats-<version>.jar`。注意先构建前端再打包：`ui/build/dist` 是前端产物的来源，`gradle clean` 会把它删掉，这时打出来的 jar 会缺少后台界面。
